# Clair 原生桌面端设计与交付边界

状态：0.3.9 Windows/Linux 试用包已在本机打包并从解压目录冷启动；尚待用户试用，尚未提 PR。现有 Web 版保持可用；桌面端不使用浏览器、WebView、本地 HTTP 服务或 Node.js 完成曲库浏览与播放。用户确认试用结果后，才分别向 Gitee 与 GitHub 提 PR。

## 产品边界

- 支持 Windows、macOS、Linux。首版使用 Qt 6/C++ + Qt Quick/QML；QML 是 Qt 场景图界面，不是网页封装。
- 桌面端保留“打开 Web 版”按钮，默认在系统浏览器打开应用内仅监听 `127.0.0.1` 的只读静态页面；可配置外部 Web 地址。原生播放与 Web 播放彼此独立，不互相暂停或抢占；选择同一个音乐根目录后，收藏、歌单和逐曲进度通过 `.Clair` 文件同步。
- 古典音乐的“作品/录音版本”视图保留为可选视图；通用的艺术家、专辑、曲目路径同等重要，导入任意流派不得要求作曲家、指挥或乐团标签。
- 当前预览版仍不声称与现有 Web Audio 均衡器、频谱、标签编辑、回收站和 LAN 模式功能对等；主题图片组、可选指纹候选匹配与内置轻量离线歌词转写已实现，但真实图片素材、AcoustID 查询及歌曲转写准确率仍待试用验证。

## 首个 PR 的验收

1. Windows、macOS、Linux 从同一份 CMake 工程构建；三平台分别有构建与启动冒烟验证。
2. 无 Node.js、WebView、Web 服务也能选择本地目录、只读扫描 FLAC/MP3/WAV、播放/暂停、拖动进度、调节音量。
3. 能显示以“艺术家/专辑/曲目”为主的列表，缺失古典标签不会阻止导入。初次扫描以文件名/路径作保守回退，不猜测元数据。
4. “打开 Web 版”可启动包内静态 Web 页面；该服务停止时原生播放器仍正常工作。
5. 原生端默认不修改音频文件或现有 `.Clair/library.json`、`.Clair/settings.json`；用户显式使用“重命名文件”时才改所选文件名。

## 数据兼容与并发

Web 版仍写入 `.Clair/library.json` schema v1 和 `.Clair/settings.json` schema v2。索引中的 `path` 包含曲库根目录名，且旧浏览器收藏可能只在 `localStorage` 中；首次连接时做一次保守迁移。原生端只读旧索引，用于显示已有资料，不把索引视为绝对真值；路径须校验仍在所选音乐根目录内。桌面端自己的设置写入用户配置目录。两端另以 `.Clair/favorites.json`、`playlists.json`、`resume.json` schema v1 共享收藏、歌单与进度，拒绝覆盖格式损坏的文件。Web 同一页面的写入串行化，桌面端使用原子替换；跨进程**同时**读改写同一文件尚无锁或 CAS，存在后写覆盖先写风险，不能称为强一致。播放保持独立；lastPath 仅主动选曲时更新，周期更新只写各曲书签。

## 歌词路线与效能门槛

能力分层，避免把“检索现成歌词”和“从音频识别歌词”混为一谈：

1. 当前预览版优先使用同名 LRC 或手动导入 LRC；用户可主动搜索 LRCLIB 并选择候选，不自动覆盖歌词。内嵌歌词尚未解析。在线歌词文本的版权独立于服务端代码许可证。
2. 没有歌词时，用户可触发后台**离线转写**。0.3.9 试用包内置 CPU 版 `whisper.cpp` CLI 与约 32 MB 的多语种 tiny-q5_1 模型；音频转换复用 Qt Multimedia 的解码后端，不额外捆绑 FFmpeg 命令行程序。用户不必自行选工具。tiny 模型以安装体积和 CPU 开销优先，模型准确率仍须用 Clair 歌曲基准实测，不能套用普通语音基准。
3. 转写生成“待校对草稿”，以行级时间戳、可编辑文本和 LRC 导出为首个交付目标；不承诺歌曲人声的逐字精确高亮。伴奏、拉长音、叠唱、说唱和纯器乐会造成错误或幻觉。
4. 转写任务后台运行、可取消、结果缓存；播放线程不等待识别。词级时间轴、Demucs 人声分离、WhisperX 强制对齐与 `faster-whisper`/`sherpa-onnx` 适配器须由实测收益证明后再加入，避免默认安装体积和计算成本膨胀。

评测集需包含授权的中英歌曲、不同流派、伴奏强弱与纯器乐。记录 CER/WER、行起止时间偏差、转写时长/音频时长、峰值内存、CPU/GPU 型号、模型量化与安装体积；没有实测前不发布“实时”或“高准确率”宣传。

## 主题图片组契约

当前已实现 v1 主题 manifest：背景 1920×1080、封面 600×600、侧栏 480×1080，裁剪框使用原图归一化坐标；应用内框选裁剪与仓库内 AI 辅助 skill 输出同一格式。保留原图，导入时生成派生图，不破坏用户素材。仍需用真实人像、横幅、竖图验证构图质量；当前 skill 是视觉判断配合确定性脚本，不宣称自动主体/人脸检测，也不上传图片。

## 平台与许可风险

- Qt Multimedia 在桌面平台通常使用 FFmpeg 后端。构建成功不等于 FLAC/MP3/WAV、无缝播放、EQ、频谱与输出设备切换均通过；需逐平台测试编解码与部署。
- 浮动歌词窗将使用独立透明、无边框窗口。Linux Wayland 合成器可能限制置顶、跨桌面和点击穿透；必须提供普通窗口模式作为退路。
- 分发前核对 Qt LGPLv3、随包 FFmpeg、`whisper.cpp`、模型权重和其他依赖的许可证及源代码/告知义务。

## 0.3.9 长时间运行与缓存排查

- 源码审计：正常空闲或重复播放固定曲库时，没有按帧生成新文件的路径；共享进度约每 10 秒原子覆盖同一个 `resume.json`。但长期积累风险包括：转写 `.lrc` 草稿无上限、崩溃可能遗留临时 WAV、本地 Web 半请求连接没有超时、快速重复歌词搜索使旧请求并存。主题成功导入后保存的图片、FLAC 元数据备份和回收站属于用户数据，不能作为垃圾自动清理；共享 `resume.json` 书签和收藏 `false` 也不应无条件删除。
- 0.3.9 新增保守缓存整理：总缓存超过 100 MB 或 256 项时，只删超过一天、哈希命名、未被当前任务及歌词设置引用的旧转写草稿；临时任务目录仅在超过 7 天且有非运行锁，或旧版无锁目录超过 30 天，且内容全是识别程序生成的旧文件时清理。清理只逐个删除已检查的文件，不递归删除未知内容。正常结束/取消的临时 WAV 仍由 `QTemporaryDir` 立即清理。已选歌词、原音频、手动 LRC、主题图均不在清理范围。
- 本地 Web 静态服务的半请求连接增加 5 秒超时；新歌词搜索或切曲会取消旧网络请求。回归测试覆盖旧/新/已选草稿、未知文件、旧临时目录和超时连接；Windows 和 Ubuntu 24.04/WSLg 各 10 项 CTest、Web 36 项测试通过。
- 0.3.9 Windows ZIP 与 Linux tar.gz 校验 SHA-256 后从新目录解压冷启动并截图通过。正常 Windows 图形平台空闲 5 分钟，62→242 秒私有内存 87.04→86.88 MB、句柄 1268→1258；程序到时正常退出，转写缓存仍是原有 2 个文件、9502 字节。这仅覆盖短时空闲状态，不是 24 小时或循环播放压力测试。`QT_QPA_PLATFORM=offscreen` 的另一次测试约一分钟时出现 Qt6Core fail-fast，正常 Windows 图形平台 90 秒和 5 分钟测试未复现，离屏结果不作为产品稳定性结论；仍需真实音乐长时播放与 macOS 验证。
